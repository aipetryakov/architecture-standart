| Код | Требования | Комментарий |
| ----| ---------- | ------------|
| F   | Функциональные (Functionality) | |
| F1  | Клиенты могут посмотреть список доступных депозитов с актуальными ставками через сайт | |
| F2  | Клиенты могут подать заявку на депозит через сайт | Клиент указывает телефон и ФИО |
| F3  | Менеджер-колл центра должен перезвонить клиенту подавшему заявку на депозит через систему кол-центра | |
| F4  | Менеджер-колл центра может предложить клиенту особые условия на депозит через систему кол-центра | |
| F5  | Клиенты могут посмотреть список доступных депозитов с актуальными ставками через интернет-банк | |
| F6  | Клиенты могут посмотреть список доступных депозитов с персонализированными ставками через интернет-банк | |
| F7  | Клиенты могут подать заявку на депозит через интернет-банк | Клиент указывает счет и сумму депозита |
| F8  | Клиенты должны подтвердить заявку на открытие депозита в интернет-банке через СМС-кода |  |
| F9  | Сотрудники бэк-офиса депозитов и кредитов должны вести ставки по депозитам в АБС | Сейас ставки по депозитам ведутся в XLS-файлах |
| F10 | Процесс согласования ставки по депозиту должен проходить в АБС | |
| F11 | Менеджер бек-офиса должен подтверждать условиям депозита в АБС | После MVP планируется автоматизация |
| F12 | При подтверждении размера ставки и открытии депозита клиент должен получить СМС-уведомление | |
| U   | Удобство использования (Usability) | |
| U1  | Интерфейс должен быть максимально удобным для клиента | |
| U2  | Необходимо придерживаться системы дизайна для приложений | Пользователи при работе должны видеть привычные цвета и брендированные элементы |
| R   | Надёжность (Reliability) | |
| R1  | Все сервисы должны работать 24/7 и быть доступны в 99,9% времени | |
| R2  | В случае сбоя основного ЦОД трафик должен переключаться на резервный ЦОД | Для интернет-банка пока не реализовано из-за небольшого кол-ва клиентов и функционала |
| P   | Производительность (Performance) | |
| P1  | Отккли по всем операциям для клиента должен занимать миллисекунды | Сейчас некоторые справочные данные загружаеются дольше секунды при проведении платежей |
| P2  | Необходимо реализовать равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД | Необходимо учесть что АБС может масштабироваться только вертикально из-за своей БД|
| S   | Поддерживаемость (Supportability) | |
| S1  | Для разрабатываемого функциоанала необходимо составлять документацию | |
| S2  | При дорабатках необходимо отдавать приоритет уже использующимся в банке технологиям | Базы данных: MS SQL и Oracle. Разработка: ASP.NET MVC 4.5 на основе .NET Framework 4.5, Delphi, Java Spring Boot |
| +R  | + Ограничения (Restrictions) | |
| +R1 | Передаваемые с сайта данные необходимо защищать с помощью механизма шифрования трафика | |
| +R2 | Передаваемые с интернет-банка данные необходимо защищать с помощью механизма шифрования трафика | |
| +R3 | Реализовать функционал отправки СМС необходимо в отдельном сервисе | Имеющийся функционал реализован в ядре системе, он требует доработок, которые может делать тольк подрядчик |
| +R4 | При необходимости использования новых технологий: они должны быть совместимы с уже использующимися, сотрудника банка должны обладать экспертизой в них | |
| +R5 | При необходимости использования брокера / очереди необходимо использовать Kafka | |
| +R6 | Функционал открытия депозита через интернет-банк необходимо реализовать в отдельном сервисе | Интернет-банк явялется монолитным решением и не совместим с Kafka |
| +R7 | Необходимо исключить прямое взаимодействие интернет-банка с API АБС | База данных АБС перегружена, сейчас интернет-банк интегрирован с БД АБС напрямую |
| +R8 | Предусмотреть возможность полной автоматизации открытия через интернет-банк депозита, накопительного счета, кредиа | Это будет реализовываться в следующих этапах|
