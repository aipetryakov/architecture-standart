### <a name="_qmphm5d6rvi3"></a>**Решение**
Диаграммы
- [контекста](context.drawio)
- [контейнеров](containers.drawio)

При принятии решении о выборе технологий руководствовался следующим:
1. Часть технологий, использующихся в системе является не подходящими для дальнейшнего долгосрочного использования:
  - MS SQL и Oracle - большие санкионные риски
  - Delphi - сложности с наймом из-за низкой поулярности
  - ASP.NET MVC 4.5 на основе .NET Framework 4.5 - последний релиз версии 4.8.1 был в 2022 году
2. В компании используется только один подходящий стек технологии, в системе колл-центра - React, Sprint Boot, PostgreSQL. Поэтому для разработки новый сервисов и интерфейсов, там где это не доабвляет значительных дополнительных расходов, испольщуется только он. Данные стек достаточно поулярен и позволяет выполнить все функциональные и не функциональные требования.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Реализовать общий сервис заявок, которым будут использовать интернет-банк, сайт, АБС, колл-центр (придется сильнее перестраивать систему колл-центра)
2. Для процесса согласования ставки использовать процессны движок, например camunda (позволит визуализировать процесс для координации поддержки, аналатики, разработки)

**Недостатки, ограничения, риски**

1. Сайт, АБС, Колл-центр имеют свои копии заявок на депозиты, с асинхронным процессом синхронизации. Данные в трех системах могут расходится в течение определенного времени.
2. Новая часть интерфейса интернет-банка по работе с депозитами выделена в отдельное React приложени, могут возникнуть сложности с бесшовным переходом клиентов между старой и новой частью интерфейса
3. Новая часть интерфейса АБС реализовывается внутри существующего монолита, на устаревших технологиях, что расширит общий тех. долг компании (хотя и позволит реализовать текущую задачу с минимальными затратами)
